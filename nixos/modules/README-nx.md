# Siemens NX 10.0 на NixOS

Да, работает. NX 10 — обычное 64-битное Linux-приложение под RHEL 6 / SLES 11,
просто оно ожидает FHS (`/usr/lib`, `/lib64`, `/bin/ksh`), которого в NixOS нет.
Решение — не «пакетировать» NX, а поставить его в `/opt` как на любом другом
дистрибутиве и запускать внутри `buildFHSEnv`.

Модуль `siemens-nx.nix` даёт:

- `nx10-env` — шелл в FHS-песочнице (в нём запускается установщик);
- `nx10` — лаунчер самого NX (`ugraf`) с уже выставленными переменными;
- пункт «Siemens NX 10.0» в меню приложений;
- `xwayland-satellite` в системных пакетах.

## Что нужно от тебя

Установочный носитель NX 10.0 for Linux x86-64 и **действующая лицензия**
(NX проверяет её через FlexNet-сервер Siemens, обойти это модуль не помогает
и не пытается).

## Порядок установки

1. Применить конфигурацию и перелогиниться в niri (нужен XWayland):

   ```sh
   sudo nixos-rebuild switch
   ```

   Проверить, что X11 поднялся:

   ```sh
   echo $DISPLAY          # должно быть :12
   xdpyinfo | head -3     # внутри nx10-env
   ```

2. Распаковать/смонтировать носитель и запустить установщик **внутри**
   песочницы — не снаружи, иначе он не найдёт `/bin/sh`-окружение:

   ```sh
   sudo mount -o loop,ro nx10.iso /mnt
   nx10-env
   # уже внутри FHS:
   cd /mnt && ./Launch.sh        # либо ./nx/install, зависит от носителя
   ```

   В качестве каталога установки указать то же, что в
   `programs.siemens-nx.baseDir` — по умолчанию `/opt/siemens/nx10`.
   Установщику нужны права записи туда: модуль создаёт каталог через
   `systemd.tmpfiles`, так что запускай `nx10-env` под `sudo` или
   заранее выдай себе права на каталог.

3. Указать лицензию в `nixos/configuration.nix`. Установщик на своём шаге
   тоже про неё спросит, но переменную окружения можно менять когда угодно —
   переустановка для этого не нужна:

   ```nix
   # сетевая (floating) лицензия — порт@хост, 28000 по умолчанию
   programs.siemens-nx.licenseServer = "28000@твой-хост";

   # либо node-locked: FlexNet принимает в той же переменной путь к файлу
   programs.siemens-nx.licenseServer = "/opt/siemens/licenses/splm.lic";
   ```

   Модуль прокидывает это значение и в `SPLM_LICENSE_SERVER`, и в старое
   `UGS_LICENSE_SERVER` — NX 10 читает оба.

   Если лицензия серверная, `.lic` скармливается не NX, а самому Siemens PLM
   License Server при его установке; NX потом ходит к нему по сети.
   Проверить, что NX видит лицензию:

   ```sh
   nx10-env
   echo $SPLM_LICENSE_SERVER
   $UGII_ROOT_DIR/lmtools lmstat -a    # если lmtools есть на носителе
   ```

4. Запуск:

   ```sh
   nx10                  # или пункт в меню
   nx10 /путь/к/model.prt
   ```

## Грабли, на которые стоит посмотреть заранее

**Локаль.** У тебя `LC_NUMERIC=ru_RU.UTF-8`, а NX понимает только десятичную
точку. С русской локалью он молча портит ввод размеров и импорт STEP/IGES.
Поэтому лаунчер принудительно ставит `LC_ALL=C` — не убирай это.

**Wayland.** Нативного Wayland у NX 10 нет и не будет, всё идёт через
XWayland. На дробном масштабе (у тебя `scale 1.75`) Motif-интерфейс будет
мылить — XWayland рисует в целочисленном масштабе и растягивает. Если мешает,
запускай NX на выходе со `scale 1` или смирись с мылом.

**Видеокарта.** У тебя AMD (Mesa). NX 10 сертифицирован под NVIDIA Quadro, на
Mesa обычно работает, но продвинутый рендер (Studio / Ray Traced Studio) может
глючить. Если NX падает на старте с ошибкой GL, попробуй софтверный рендер
для диагностики:

```sh
nx10-env
LIBGL_ALWAYS_SOFTWARE=1 $UGII_ROOT_DIR/ugraf
```

**Лицензионный демон.** `lmgrd`/`ugslmd` — такие же FHS-бинарники, их тоже надо
запускать из `nx10-env`. FlexNet кладёт lock-файлы в `/usr/tmp/.flexlm`;
если демон ругается на этот путь, создай `sudo mkdir -p /usr/tmp` (в NixOS
такого каталога нет). Постоянный сервер удобнее оформить отдельным
systemd-юнитом с `ExecStart = "${nxEnv}/bin/nx10-env ..."`.

**Не хватает библиотеки.** Посмотреть, чего не достаёт:

```sh
nx10-env
ldd $UGII_ROOT_DIR/ugraf | grep 'not found'
```

и добавить недостающее:

```nix
programs.siemens-nx.extraPkgs = pkgs: [ pkgs.libpng12 ];
```

`libpng12` помечен в nixpkgs как insecure, для него дополнительно понадобится
`nixpkgs.config.permittedInsecurePackages = [ "libpng-1.2.59" ]`.
